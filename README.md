# Passport Admin

Overworld 운영자 웹을 위한 독립 React·TypeScript·Vite 앱입니다.

## 현재 구현

학교 로그인과 등록된 운영자 권한으로 관리 화면에 접근합니다. API 설정 `ADMIN_MFA_REQUIRED=true`일 때만 인증 앱의 6자리 코드를 추가 확인합니다. 일반 회원 로그인만으로 관리 권한을 얻을 수 없습니다. API 연결 실패, 학교 재로그인 필요, 추가 인증 만료를 구분해 안내합니다.

- 운영 현황: 실제 회원·Minecraft 연결·접근 정지 수, 명부와 동기화 상태, 등록된 서버
- 회원 관리: 실명·전체 학번·Minecraft·Discord 통합 검색, 전체 학번을 보여 주는 목록·확장 상세, 회원 필터·정렬·커서 페이지, 개인별 접근 제한과 계정 삭제
- 서버 관리: 플러그인 자동 발견, Paper 응답·프록시 등록 상태, 서버 사용 여부, 명부·전체 활성 회원·선택 회원 접근 설정
- 명부 동기화: 변경 미리보기, 위험 변경의 명시적 확인, 검토한 내용의 digest를 포함한 반영 요청
- 운영 기록: 최근 100건의 행위자·대상·변경 내용 조회

등록 키와 인증 코드는 컴포넌트 메모리에서만 다루며 브라우저 저장소에 보관하지 않습니다. MFA 성공 시 회전된 세션의 CSRF 토큰을 다시 조회합니다. 추가 인증 만료 또는 서버의 권한 거부 시 관리 데이터를 화면에서 제거합니다. 학교 비밀번호를 이 앱에서 입력받지 않습니다.

전체 학번은 관리자 API가 반환하는 학교 검증 값을 표시합니다. 아직 학번이 저장되지 않은 계정이나 이전 API 응답에는 `학교 재인증 필요`를 표시하며 입학 연도나 이름으로 추정하지 않습니다. 별도 개인정보 동의 단계를 추가하지 않습니다.

## 로컬 개발

Node.js 24와 별도 `passport-api`가 필요합니다. API의 허용 Origin에 실제 접속할 `http://localhost:5174` 등을 등록하세요.

```sh
npm ci
npm run dev
npm run check
npm run build
```

Vite 기본 포트는 5174입니다. `/v1` 요청은 기본 `http://127.0.0.1:3000`으로 프록시됩니다. `API_PROXY_TARGET`은 개발 서버의 프록시 대상만 변경하며 브라우저 API 비밀값이 아닙니다. API 서비스 토큰을 브라우저에 넣지 않습니다.

## 컨테이너

```sh
docker build -t passport-admin:dev .
```

비특권 nginx가 8080 포트에서 정적 웹을 제공하고 같은 네트워크의 `api:3000`으로 `/v1/`를 프록시합니다. `Host`에 포트를 포함한 원래 값을 유지합니다. `/healthz`는 정적 웹 프로세스의 상태만 확인합니다. 운영 TLS·도메인·Compose·비밀값은 비공개 운영 저장소에서 관리합니다.

브라우저 쿠키는 포트만으로 격리되지 않습니다. 현재 API는 포털·관리자 쿠키 이름과 세션 audience를 분리하며, 운영에서는 별도 호스트의 host-only 쿠키와 관리 세션 정책을 적용해야 합니다. 관리 API의 권한·MFA 검사는 항상 서버가 수행하며, 화면의 차단 상태만으로 보안 경계를 만들지 않습니다.

## 운영 범위

최초 등록에는 서버 운영자가 별도로 제공한 부트스트랩 코드가 필요합니다. 여러 운영자의 추가·삭제, MFA 복구·교체는 현재 화면에 포함하지 않습니다. 모든 접속에는 활성 회원 자격이 필요합니다. 서버 관리에서 접속 대상을 명시적으로 설정하며, 새로 발견된 서버는 기본 비활성입니다. 회원 관리의 개인별 제한은 서버에서 허용한 범위를 좁힙니다. 관리 요청 성공과 실제 게임 서버의 정책 반영은 별도로 확인해야 합니다.

학교 로그인과 실제 Google Sheets 동기화에는 별도 API의 운영 설정이 필요합니다. [검증 기록](docs/verification.md)에서 브라우저 합성 응답 검증과 실제 연동 검증의 범위를 구분합니다.

비공개 계약 저장소를 CI나 빌드 의존성으로 요구하지 않으며 다른 저장소의 소스를 상대 경로로 참조하지 않습니다.

## 화면 기준

ALMS v4 A의 중립 회색·블루 레이아웃과 사용자가 지정한 Pretendard를 적용했습니다. 서체·아이콘을 자체 호스팅하며 외부 CDN을 사용하지 않습니다. 치수·색상·출처는 [화면 기준과 에셋](docs/design-system.md)을 참고하세요.


## Discord 봇 관리

별도 **Discord 봇** 메뉴에서 현재 회원 역할 ID, 현재 학기, 최대 40개의 누적 학기 역할 매핑과 닉네임 동기화를 관리합니다. Discord 서버와 학교 인증 역할은 운영 환경에 고정되어 읽기 전용으로 표시합니다. 서버가 제공한 revision으로 저장 충돌을 검사하며, 다른 운영자의 변경을 덮어쓰지 않습니다. 현재 학기를 바꾸기 전에 회원 명부를 해당 학기 기준으로 갱신해야 합니다. 학기 변경은 명부의 열/헤더를 자동 변경하지 않으며 이전 학기 이력은 유지합니다. 현재 학기를 지정하면 같은 학기의 역할 매핑이 필요하고 역할 ID·학기 중복과 @everyone은 허용하지 않습니다.

- `GET /v1/admin/discord`: 설정과 연결 수·역할/닉네임 처리 대기·실패 수
- `PUT /v1/admin/discord`: 수정 가능한 설정과 `expectedRevision`, CSRF로 저장
- `POST /v1/admin/discord/reconcile`: 현재 revision과 CSRF로 재동기화 요청

설정 저장·재동기화 접수와 봇의 실제 반영 완료를 구분합니다. 화면이 보일 때 15초 간격으로 상태를 갱신하며 편집 중인 입력은 유지합니다. 닉네임 실패는 역할 성공과 별개이고, 서버 소유자나 봇과 같거나 높은 역할의 계정은 닉네임을 바꿀 수 없음을 안내합니다. 봇 토큰은 입력하거나 응답에서 받지 않습니다.

`npm run check`, `npm run test:browser-discord`로 단위·루프백 합성 브라우저 회귀를 실행합니다. 기존 설치된 agent-browser 실행 파일을 사용하려면 `PASSPORT_AGENT_BROWSER=/path/to/agent-browser`를 지정할 수 있습니다. 지정하지 않으면 `npx agent-browser@0.38.1`을 사용합니다.

nginx는 `/v1/`과 `/v2/`를 같은 API로 전달합니다. CI의 `test/nginx-proxy.sh`는 실제 nginx 컨테이너와 폐기 가능한 가상 API로 GET/POST 경로·Host·보안 헤더·SPA 응답을 검사하며 운영 서비스에 접속하지 않습니다.
