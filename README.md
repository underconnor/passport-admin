# Passport Admin

Overworld 운영자 웹을 위한 독립 React·TypeScript·Vite 앱입니다.

## 현재 구현

학교 로그인과 등록된 운영자 권한으로 관리 화면에 접근합니다. API 설정 `ADMIN_MFA_REQUIRED=true`일 때만 인증 앱의 6자리 코드를 추가 확인합니다. 일반 회원 로그인만으로 관리 권한을 얻을 수 없습니다. API 연결 실패, 학교 재로그인 필요, 추가 인증 만료를 구분해 안내합니다.

- 운영 현황: 실제 회원·Minecraft 연결·접근 정지 수, 명부와 동기화 상태, 등록된 서버
- 회원 관리: 실명·전체 학번·Minecraft·Discord 통합 검색, 전체 학번을 보여 주는 목록·확장 상세, 회원 필터·정렬·커서 페이지, 개인별 접근 제한과 계정 삭제
- 서버 관리: 플러그인 자동 발견, 표시명·이동 명령어 이름, Paper 응답·프록시 등록 상태, 서버 사용 여부, 명부·전체 활성 회원·선택 회원 접근 설정
- 명부 동기화: 변경 미리보기, 위험 변경의 명시적 확인, 검토한 내용의 digest를 포함한 반영 요청
- 운영 기록: 최근 100건의 행위자·대상·변경 내용 조회
- 운영자 관리: 학교 인증 계정 검색·선택, 24시간 단회 초대·대상자의 수락, 역할 변경·권한 회수·초대 취소

등록 키와 인증 코드는 컴포넌트 메모리에서만 다루며 브라우저 저장소에 보관하지 않습니다. MFA 성공 시 회전된 세션의 CSRF 토큰을 다시 조회합니다. 추가 인증 만료 또는 서버의 권한 거부 시 관리 데이터를 화면에서 제거합니다. 학교 비밀번호를 이 앱에서 입력받지 않습니다.

전체 학번은 관리자 API가 반환하는 학교 검증 값을 표시합니다. 아직 학번이 저장되지 않은 계정이나 이전 API 응답에는 `학교 재인증 필요`를 표시하며 입학 연도나 이름으로 추정하지 않습니다. 별도 개인정보 동의 단계를 추가하지 않습니다.

## 로컬 개발

Node.js 24와 별도 `passport-api`가 필요합니다. API의 허용 Origin에 실제 접속할 `http://localhost:5174` 등을 등록하세요.

```sh
npm ci
npm run dev
npm run check
npm run build
```

Vite 기본 포트는 5174입니다. `/v1` 요청은 기본 `http://127.0.0.1:3000`으로 프록시됩니다. `API_PROXY_TARGET`은 개발 서버의 프록시 대상만 변경하며 브라우저 API 비밀값이 아닙니다. API 서비스 토큰을 브라우저에 넣지 않습니다.

## 컨테이너

```sh
docker build -t passport-admin:dev .
```

비특권 nginx가 8080 포트에서 정적 웹을 제공하고 같은 네트워크의 `api:3000`으로 `/v1/`를 프록시합니다. `Host`에 포트를 포함한 원래 값을 유지합니다. `/healthz`는 정적 웹 프로세스의 상태만 확인합니다. 운영 TLS·도메인·Compose·비밀값은 비공개 운영 저장소에서 관리합니다.

브라우저 쿠키는 포트만으로 격리되지 않습니다. 현재 API는 포털·관리자 쿠키 이름과 세션 audience를 분리하며, 운영에서는 별도 호스트의 host-only 쿠키와 관리 세션 정책을 적용해야 합니다. 관리 API의 권한·MFA 검사는 항상 서버가 수행하며, 화면의 차단 상태만으로 보안 경계를 만들지 않습니다.

## 운영 범위

최초 등록에는 서버 운영자가 별도로 제공한 부트스트랩 코드가 필요합니다. 이후 운영자 추가는 총괄 운영자가 계정을 지정해 초대하고, 대상자가 관리자 페이지에서 본인의 학교 계정으로 로그인해 수락합니다. MFA 복구·교체 UI는 포함하지 않습니다. 게임 접속 대상은 서버별 정책을 따릅니다. 서버 관리에서 접속 대상을 명시적으로 설정하며, 새로 발견된 서버는 기본 비활성입니다. 회원 관리의 개인별 제한은 서버에서 허용한 범위를 좁힙니다. 관리 요청 성공과 실제 게임 서버의 정책 반영은 별도로 확인해야 합니다.

학교 로그인과 실제 Google Sheets 동기화에는 별도 API의 운영 설정이 필요합니다. [검증 기록](docs/verification.md)에서 브라우저 합성 응답 검증과 실제 연동 검증의 범위를 구분합니다.

비공개 계약 저장소를 CI나 빌드 의존성으로 요구하지 않으며 다른 저장소의 소스를 상대 경로로 참조하지 않습니다.

## 화면 기준

ALMS v4 A의 중립 회색·블루 레이아웃과 사용자가 지정한 Pretendard를 적용했습니다. 서체·아이콘을 자체 호스팅하며 외부 CDN을 사용하지 않습니다. 치수·색상·출처는 [화면 기준과 에셋](docs/design-system.md)을 참고하세요.


## Discord 봇 관리

별도 **Discord 봇** 메뉴에서 현재 회원 역할 ID, 현재 학기, 최대 40개의 누적 학기 역할 매핑과 닉네임 동기화를 관리합니다. Discord 서버와 학교 인증 역할은 운영 환경에 고정되어 읽기 전용으로 표시합니다. 서버가 제공한 revision으로 저장 충돌을 검사하며, 다른 운영자의 변경을 덮어쓰지 않습니다. 현재 학기를 바꾸기 전에 회원 명부를 해당 학기 기준으로 갱신해야 합니다. 학기 변경은 명부의 열/헤더를 자동 변경하지 않으며 이전 학기 이력은 유지합니다. 현재 학기를 지정하면 같은 학기의 역할 매핑이 필요하고 역할 ID·학기 중복과 @everyone은 허용하지 않습니다.

- `GET /v1/admin/discord`: 설정과 연결 수·역할/닉네임 처리 대기·실패 수
- `PUT /v1/admin/discord`: 수정 가능한 설정과 `expectedRevision`, CSRF로 저장
- `POST /v1/admin/discord/reconcile`: 현재 revision과 CSRF로 재동기화 요청

설정 저장·재동기화 접수와 봇의 실제 반영 완료를 구분합니다. 화면이 보일 때 15초 간격으로 상태를 갱신하며 편집 중인 입력은 유지합니다. 닉네임 실패는 역할 성공과 별개이고, 서버 소유자나 봇과 같거나 높은 역할의 계정은 닉네임을 바꿀 수 없음을 안내합니다. 봇 토큰은 입력하거나 응답에서 받지 않습니다.

`npm run check`, `npm run test:browser-discord`로 단위·루프백 합성 브라우저 회귀를 실행합니다. 기존 설치된 agent-browser 실행 파일을 사용하려면 `PASSPORT_AGENT_BROWSER=/path/to/agent-browser`를 지정할 수 있습니다. 지정하지 않으면 `npx agent-browser@0.38.1`을 사용합니다.

nginx는 `/v1/`과 `/v2/`를 같은 API로 전달합니다. CI의 `test/nginx-proxy.sh`는 실제 nginx 컨테이너와 폐기 가능한 가상 API로 GET/POST 경로·Host·보안 헤더·SPA 응답을 검사하며 운영 서비스에 접속하지 않습니다.

## 운영자 초대와 역할

| 역할 | 범위 |
| --- | --- |
| 총괄 운영자 (`owner`) | 모든 관리 기능, 운영자 초대·역할 변경·권한 회수 |
| 운영자 (`operator`) | 일반 회원·서버·명부·Discord 관리, 통계·운영 기록 조회 |
| 조회 전용 (`viewer`) | 관리 정보 조회, 변경 작업 불가 |

총괄 운영자는 **운영자 관리 → 계정 검색 → 초대**에서 대상과 역할을 확인합니다. 초대는 선택된 학교 계정에 귀속되며 발급 후 24시간 내 한 번 수락할 수 있습니다. 별도의 초대 토큰이나 공유 링크를 발급·저장하지 않습니다. 대상자는 관리자 웹에서 학교 로그인 후 **초대 수락하고 시작하기**를 선택합니다. 수락 전에는 관리 권한이 부여되지 않습니다.

본인의 역할 변경·회수와 마지막 총괄 운영자 회수를 제한합니다. 일반 운영자는 다른 운영자 계정의 접근 변경·연결 해제·회원 삭제로 운영자 관리를 우회할 수 없습니다. 역할 변경·회수 시 API가 대상자의 관리자 세션을 종료하며, 화면은 30초 간격·탭 복귀·서버의 권한 거부 시 상태를 다시 확인하고 이전 편집창을 제거합니다. 역할별 버튼 제한과 별개로 최종 인가는 API가 수행합니다. 권한 응답이 없는 구 API에서는 변경 기능을 표시하지 않습니다.

기존 운영자는 서버 마이그레이션으로 총괄 운영자 역할을 유지합니다. 현재 운영 환경은 OTP를 요구하지 않으며, `ADMIN_MFA_REQUIRED=true` 환경의 새 초대 수락은 API에서 제한됩니다. 기존 등록·MFA 흐름은 유지합니다.

`npm run test:browser-operators`는 실제 운영 데이터를 사용하지 않고, 루프백 합성 응답으로 초대·수락·역할별 제어와 데스크톱/모바일 화면을 확인합니다. API 권한·트랜잭션 테스트와 실제 운영 배포는 별도 단계입니다.

전체·서버별·사용자별 통계는 플레이어 처치 횟수와 대략적인 이동 거리를 포함한 8개 지표를 제공합니다. `playerKills`는 몹 처치와 분리하고, `distanceCm`는 m/km로 변환합니다. 새 필드가 없는 이전 응답에는 0을 표시합니다.

## 서버 표시명과 이동 명령어 이름

**서버 관리 → 서버 펼치기 → 접근 및 설정**에서 표시 이름과 이동 명령어 이름을 각각 바꿉니다. 목록에는 표시 이름과 `/서버 이동명령어이름`을 함께 표시하고, 설정창은 입력한 값의 명령어 예시를 바로 보여줍니다. 예를 들어 표시 이름이 `약탈 월드`, 이동 명령어 이름이 `약탈`이면 `/서버 약탈`로 이동합니다.

명령어 이름은 NFC로 정규화하고 영문을 소문자로 저장합니다. 한글 완성형·영문·숫자·밑줄·하이픈만 1~64자까지 허용하며 앞뒤를 포함한 공백은 거절합니다. 다른 서버의 명령어 이름이나 내부 ID와 겹치면 저장하지 않고 안내합니다. 화면의 사전 검사 뒤에도 API의 `server_command_conflict` 검증이 최종 기준입니다. 플러그인의 고정 내부 ID는 변경하지 않습니다.

쓰기가 허용된 운영자만 수정할 수 있으며, 권한이 내려가면 열린 편집창도 제거합니다. 저장 시 CSRF와 기존 `expectedUpdatedAt`을 보내고 설정 충돌은 덮어쓰지 않습니다. 선택 회원·접속 정책·통계 설정을 함께 보존합니다. 이 화면은 `commandName` 응답과 저장을 지원하는 API를 먼저 배포한 뒤 공개합니다. API를 이전 버전으로 되돌려 필드가 빠지면 내부 ID로 명령어를 표시하고 명령어 편집을 비활성화합니다. 이때 기존 표시명·접근 설정 저장은 `commandName`을 보내지 않아 계속 사용할 수 있습니다.

`test/server-settings.test.mjs`와 `test/statistics-controls.browser.mjs`의 `server command` 시나리오는 정규화·유효성·중복·권한·revision·불변 ID·저장 payload를 검사합니다. 합성 화면의 데스크톱·모바일 결과는 실제 운영 서버 변경과 구분합니다.

## 통계 수집과 초기화

**서버 관리 → 서버 펼치기 → 접근 및 설정 → 이 서버 통계 수집**에서 서버별로 변경합니다. 로비 기본값은 중앙 API가 관리하며 화면은 응답을 그대로 표시합니다. 끄면 새 통계 수집과 일반 합계 표시를 중지하고 보관 기록은 유지합니다. 개인별 수집 ON/OFF는 제공하지 않으며 유효한 개인정보 동의와 관리자 서버 설정으로 수집합니다. 변경 시 다른 서버에서 전송 대기 중인 기록도 제외될 수 있습니다. 이미 저장된 다른 서버의 기록은 유지합니다.

초기화는 쓰기 가능한 관리자만 사용할 수 있습니다. **플레이 통계**에서 전체/서버별 범위를 선택하거나, **회원 관리 → 회원 펼치기 → 플레이 통계**에서 해당 회원의 모든 서버 기록을 선택합니다. 영향을 확인한 뒤 `통계 초기화`를 입력하고 확인 체크 후 실행합니다. 제외 서버의 보관 기록도 해당 범위라면 포함되며 실행 시점까지 쌓인 기록을 지웁니다. 계정·동의·수집 설정은 유지합니다. 다른 운영자 계정의 통계가 포함되면 총괄 운영자 권한이 필요합니다. 최종 권한과 범위 검증은 API가 수행합니다.

대상이 달라지거나 다른 초기화로 revision이 변경되면 다시 미리 보기를 받아야 합니다. 정상적인 카운터 증가는 미리 보기를 무효화하지 않습니다. 조회 전용은 설정·초기화 버튼을 표시하지 않으며 권한 변경 시 열린 초기화창을 제거합니다.

`npm run test:browser-statistics-controls`는 운영 기록을 건드리지 않는 루프백 합성 응답으로 수집 설정·미리 보기·확인·충돌·권한을 검증합니다.

## 통계 엑셀과 기간 조회

수집이 꺼진 서버는 통계 선택 목록에서 숨깁니다. 서버 설정 목록에는 계속 표시하므로 다시 켤 수 있습니다. 통계 화면은 최초·최근 수집 시점과 일별 기록을 제공합니다. 조회 기간은 한국 날짜 기준 366일 이내이며 일별 기록은 기능 적용 후 서버 수신일부터 집계합니다. 이전 누적 기록을 임의로 일별 배분하지 않습니다.

**플레이 통계**의 사용자 범위에서 기본 `전체 사용자` 또는 `소모임 회원만`을 선택합니다. 선택한 범위의 합계·일별 기록·인원은 중앙 API가 계산하며, 서버·기간 선택과 함께 적용합니다. 개인 회원 상세에는 사용자 범위 필터를 표시하지 않습니다.

**플레이 통계 → 엑셀 다운로드**는 현재 사용자 범위·선택 서버·조회 기간을 적용합니다. 파일을 준비하는 동안 범위 선택을 잠가 화면과 다운로드 조건이 달라지지 않게 합니다. 소모임 회원만 보기에서는 전체/서버 통계 초기화를 숨기며, `전체 사용자`로 돌아온 뒤 사용할 수 있습니다. **회원 관리 → 회원 펼치기 → 플레이 기록**에서는 해당 회원만 내려받습니다. 파일은 사용자 ID, 전체 학번, 이름과 서버별 통계를 담으며 owner/operator만 받을 수 있습니다. 서버는 다운로드를 감사 기록에 남기며 화면은 파일을 로컬 저장소에 보관하지 않습니다.

## 매뉴얼 관리

**매뉴얼 관리**에서 문서 제목과 웹에 게시한 Notion 주소를 저장합니다. 사용자 포털의 **매뉴얼** 탭에 표시됩니다. 페이지 안에 표시하려면 Notion의 게시 → 이 페이지 임베드에서 복사한 코드의 `src` 주소만 추가합니다. 공개 문서와 같은 Notion 사이트·페이지여야 하며 다른 사이트, 임의 HTML을 실행하지 않습니다. 주소를 비우고 저장하면 등록을 해제합니다. 조회 전용 운영자는 수정할 수 없고 동시 변경은 revision 충돌로 막습니다.

## 상태 감시와 연결 키

**상태 감시**는 학교 인증·명부 동기화·정책·변경 전송의 성공, 거절, 실패, 처리 시간을 표시합니다. API 프로세스가 시작된 뒤의 집계이며 재시작하면 초기화됩니다. 개인정보·토큰을 표시하지 않습니다.

총괄 운영자의 **서비스 연결 키**에서 Paper/Velocity/Discord별 권한, 쓰기 대상 서버, 만료일을 정해 키를 발급합니다. 키 원문은 발급 직후에만 표시되고 페이지를 떠나면 지워집니다. 새 키를 서비스에 적용한 뒤 기존 키를 회수하는 순서로 교체합니다. 회수는 다음 API 요청부터 반영되며 진행 중 요청의 취소를 보장하지 않습니다. Paper의 서버 범위는 통계·접속·상태 쓰기를 제한하고 정책·변경 조회는 네트워크 전체에 적용됩니다.
