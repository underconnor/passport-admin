# Passport Admin

Overworld 운영자 웹을 위한 독립 React·TypeScript·Vite 앱입니다.

## 현재 구현

실제 API로 세션과 `GET /v1/admin/overview` 접근 상태를 확인합니다. 운영자 등록·MFA가 준비되지 않은 현재 API는 관리 요청을 거부하며, 화면도 **운영자 인증 필요** 상태를 표시합니다. API 연결 실패와 권한 부족은 별도로 안내합니다.

회원 수, 동기화 상태, 감사 기록을 가짜 데이터로 표시하지 않습니다. 회원·서버 권한 변경 UI, 운영자 부트스트랩, MFA 로그인은 아직 구현하지 않았습니다. 일반 회원 로그인으로 관리 권한을 얻을 수 없습니다.

## 로컬 개발

Node.js 24와 별도 `passport-api`가 필요합니다. API의 허용 Origin에 실제 접속할 `http://localhost:5174` 등을 등록하세요.

```sh
npm ci
npm run dev
npm run check
npm run build
```

Vite 기본 포트는 5174입니다. `/v1` 요청은 기본 `http://127.0.0.1:3000`으로 프록시됩니다. `API_PROXY_TARGET`은 개발 서버의 프록시 대상만 변경하며 브라우저 API 비밀값이 아닙니다. API 서비스 토큰을 브라우저에 넣지 않습니다.

## 컨테이너

```sh
docker build -t passport-admin:dev .
```

비특권 nginx가 8080 포트에서 정적 웹을 제공하고 같은 네트워크의 `api:3000`으로 `/v1/`를 프록시합니다. `Host`에 포트를 포함한 원래 값을 유지합니다. `/healthz`는 정적 웹 프로세스의 상태만 확인합니다. 운영 TLS·도메인·Compose·비밀값은 비공개 운영 저장소에서 관리합니다.

브라우저 쿠키는 포트만으로 격리되지 않습니다. 현재 API는 포털·관리자 쿠키 이름과 세션 audience를 분리하며, 운영에서는 별도 호스트의 host-only 쿠키와 관리 세션 정책을 적용해야 합니다. 관리 API의 권한·MFA 검사는 항상 서버가 수행하며, 화면의 차단 상태만으로 보안 경계를 만들지 않습니다.

## 다음 단계

1. 서버에서 제한된 운영자 등록과 MFA 정책을 구현합니다.
2. 승인된 관리자 API 계약에 따라 회원·동기화·감사 읽기 화면을 연결합니다.
3. 권한 부여·회수는 재인증, 조치 사유, 감사 기록, 충돌 검사를 포함해 구현합니다.

비공개 계약 저장소를 CI나 빌드 의존성으로 요구하지 않으며 다른 저장소의 소스를 상대 경로로 참조하지 않습니다.

## 화면 기준

ALMS v4 A의 중립 회색·블루 레이아웃과 사용자가 지정한 Pretendard를 적용했습니다. 서체·아이콘을 자체 호스팅하며 외부 CDN을 사용하지 않습니다. 치수·색상·출처는 [화면 기준과 에셋](docs/design-system.md)을 참고하세요.
