# 관리자 웹 구현 범위

## 운영자 접근

학교 인증과 운영자 권한을 분리합니다. API가 학교 인증 유효 기간, 명시적 운영자 등록, 관리 호스트, 15분의 MFA 유효 기간을 검사합니다. 프론트엔드는 API 응답에 맞춰 화면을 열거나 닫으며 자체적으로 권한을 부여하지 않습니다.

최초 운영자는 학교 로그인 후 별도로 받은 부트스트랩 코드로 인증 앱 키를 발급받습니다. 수동 등록 키는 해당 화면에서만 표시하고 MFA 완료·로그아웃·화면 이탈 시 제거합니다. 이미 등록한 운영자는 인증 앱 코드만 입력합니다. 등록 중 페이지를 닫아 키를 잃은 경우 부트스트랩 코드로 미완료 키를 다시 발급할 수 있습니다.

MFA 성공 후 세션 쿠키와 CSRF 토큰이 회전하므로 세션 정보를 다시 읽습니다. 모든 변경 요청은 쿠키와 CSRF를 사용합니다. 서비스 토큰, 학교 자격 증명, 장기 세션 토큰을 브라우저 코드나 저장소에 넣지 않습니다.

## 구현한 기능

| 기능 | 동작 |
| --- | --- |
| 운영 현황 | 실제 통계, 명부 유효 기간, 동기화 상태, 서버 목록 |
| 회원 조회 | 커서 페이지네이션, 학교·명부 상태, Minecraft 연결, 직접 입력 Discord ID |
| 접근 제한 | 이용 정지와 명부 허용 범위의 추가 제한. 새로운 권한 부여는 하지 않음 |
| 연결 해제 | 대상·영향 확인 체크 후 Minecraft 연결 해제 요청 |
| 명부 미리보기 | 시트의 신규 결과·기존 인원·활성 인원·위험 변경 확인 |
| 명부 반영 | 위험 변경은 명시적 확인 필요. 검토한 digest를 항상 함께 전송 |
| 운영 기록 | 최근 100건의 행위자·대상·변경 내용 표시 |

명부가 미리보기 이후 변경되거나 만료되면 승인 상태를 폐기하고 새 미리보기를 요구합니다. 시트를 직접 수정하거나 동기화 실패를 회원 탈퇴로 해석하지 않습니다. Discord ID는 소유권 미확인 사용자 입력값이며 관리자가 보았다는 이유로 인증 상태가 바뀌지 않습니다.

## 아직 포함하지 않은 기능

여러 운영자의 추가·삭제, 인증 앱 복구·교체, 관리 조치 사유 입력, 게임 서버별 실시간 적용 확인은 현재 API/UI 범위에 포함하지 않습니다. 관리 요청 성공을 실제 접속 차단 완료로 표현하지 않습니다.

학교·명부 운영 설정과 최초 운영자 등록이 완료되어야 실제 데이터로 전체 흐름을 확인할 수 있습니다. 프론트엔드 빌드와 합성 API 브라우저 검증은 실제 학교 로그인이나 실회원 변경 검증을 대신하지 않습니다.
