# 관리자 웹 구현 계획

## 운영자 접근

- 일반 회원 인증과 운영자 역할을 분리합니다. 학생·회원이라는 이유로 운영자 권한을 부여하지 않습니다.
- API가 세션, 명시적인 운영자 역할, 요구되는 MFA 상태를 모두 검사합니다.
- 초기 운영자 등록은 별도 운영 절차로 제한하고 공개 회원가입에서 운영자 역할을 선택할 수 없게 합니다.
- 관리 요청은 CSRF 방어를 적용하고 서버에서 감사 기록을 남깁니다.
- 필요한 개인정보만 기본 화면에 표시하고 전체 학적 자료나 학교 세션 원문은 제공하지 않습니다.

## 구현 범위

| 기능 | 동작 |
| --- | --- |
| 회원 조회 | 학교 검증·명부 상태·Minecraft 연결·접근 범위 확인 |
| 동기화 조회 | 최근 성공 시점, 실패 사유, 반영 예정 변경 확인 |
| 재동기화 | API에 Google Sheets 읽기 재시도 요청 |
| 서버 정책 | 특정 서버 접근 부여·회수, 만료·조치 사유 기록 |
| 이용 정지 | 중앙 정책에 정지를 반영하고 접속 중 사용자 처리 결과 확인 |
| 연결 검토 | 계정 충돌·해제·재연결을 정해진 절차로 처리 |
| 감사 기록 | 누가 언제 어떤 대상을 변경했는지 조회 |

Sheets를 직접 수정하거나 동기화 오류를 회원 탈퇴로 자동 처리하지 않습니다. 동기화 반영 기준과 대량 삭제 보호는 API에서 결정합니다.

Discord ID는 사용자 입력값으로만 보여 줍니다. 관리자가 값을 보았다는 이유로 소유권 확인 상태로 전환하지 않으며, 이 값으로 서버 권한·운영자 역할을 부여하지 않습니다.

## 구현 순서와 완료 조건

1. 읽기 화면: API 인가 실패와 개인정보 최소 표시를 확인합니다.
2. 변경 화면: 대상과 변경 내용을 확인한 뒤 사유를 기록합니다. API가 변경 충돌과 권한을 다시 검사합니다.
3. 감사 화면: 변경 전후 값과 행위자를 추적할 수 있게 합니다. 비밀값은 기록하지 않습니다.
4. 연동 검증: 운영자 역할 없는 계정, MFA 미충족 세션, 만료 세션으로 관리 작업이 거부되는지 확인합니다.
5. 회수 검증: 관리 요청 성공과 실제 게임 접근 회수 결과를 구분해서 표시합니다.

현재 React·Vite 앱의 관리 API 접근 차단 화면을 구현했습니다. 운영자 등록, MFA와 관리 기능은 아직 제공하지 않습니다.
