# 관리자 웹 검증

사용자 본인의 실제 학교 로그인·최초 등록·인증 앱 TOTP 확인 후 관리 화면 진입을 확인했습니다. 서버에서도 활성 관리자 1명, TOTP 확인 기록과 유효한 MFA 세션 1명을 확인했습니다. 아래 합성 UI 검사는 실회원 변경을 대신하지 않으며, 실제 Minecraft 연결 후 권한 회수 시험은 별도로 진행합니다.

검증일: 2026-09-30.

## 관리 기능 구현 후 검증

독립 TypeScript 검사와 Vite production build를 통과했습니다. React 구성의 의존성·요청 정리·민감한 상태 수명을 검토했으며 `git diff --check`도 통과했습니다.

브라우저 기능 검증은 운영 API 계약과 같은 응답을 제공하는 **루프백 합성 API**에서 수행했습니다. 모든 이름·회원·키·코드는 가상 데이터입니다. 실제 학교 로그인, 실회원 변경, 실제 명부 반영을 수행했다는 의미가 아닙니다.

- 최초 등록 코드 입력 → 인증 앱 수동 등록 키 표시 → 6자리 MFA → 관리 화면 진입
- MFA 후 CSRF 값 회전, 새 CSRF로 관리 변경 요청 성공
- MFA 성공 후 등록 키의 DOM 제거, localStorage·sessionStorage 저장 0건
- 잘못된 MFA 코드 안내와 입력값 제거
- 실제 응답에 따른 통계와 명부·서버 현황 표시
- 회원 커서 페이지네이션, 접근 정지와 명부 범위 내 서버 제한 저장
- 명부가 허용하지 않은 서버는 선택할 수 없음
- Minecraft 연결 해제는 확인 체크 전 비활성화, 승인 후 목록 갱신
- 위험 명부 미리보기는 승인 전 반영 비활성화, 승인 후 검토한 digest 전송
- `409 approval_mismatch` 응답 시 승인·미리보기 제거와 재확인 안내
- 운영 기록 조회와 변경 내용 펼치기
- 서버의 MFA 만료 응답 후 관리 데이터·메뉴 제거와 추가 인증 화면 복귀
- 로그아웃 후 학교 로그인 화면 표시
- 학교 로그인 오류 콜백 안내와 주소의 `auth_error` 제거
- 브라우저 런타임 오류 없음

## 화면 검증

- ALMS v4 A 레이아웃과 사용자 지정 Pretendard 유지
- 데스크톱 1440×900의 등록·운영 현황·회원·명부 화면 확인
- 모바일 390×844의 운영 기록·MFA·명부 화면 확인, 가로 넘침 없음
- 사이드바 216px, 상단 바 64px, 주 버튼 `#1B64DA`
- Pretendard Variable 폰트의 실제 `loaded` 상태 확인

## 이전 배포 검증 이력

관리 기능 추가 전 실제 개발 API에 배포한 UI에서 접근 거부 안내, 포털 로그인과 관리자 세션 분리, HTML의 CSP·Referrer-Policy·X-Frame-Options·nosniff·no-store를 확인했습니다. 당시 폰트 요청 HTTP 200과 2,057,688바이트도 확인했습니다. 이 이력은 이번 관리자 기능의 운영 배포 검증을 대신하지 않습니다.

## 남은 실제 연동 검증

운영 설정과 최초 운영자 등록 이후 학교 로그인 → 실제 인증 앱 MFA → 실제 회원 조회, 실제 Google Sheets 변경 미리보기·반영을 확인해야 합니다. 게임 서버의 접속 중 정책 회수와 계정 연결 해제 반영도 별도 검증 대상입니다. 이 웹 저장소의 브라우저 합성 API 검증과 API 저장소의 DB·인가 검증은 서로 다른 범위입니다.

## 운영 HTTPS 익명 브라우저 확인

2026-09-30, 배포된 관리자 HTTPS 주소를 사용자의 로그인 세션과 분리된 브라우저에서 확인했습니다.

- 1440×900·390×844에서 학교 로그인 안내 정상 표시, 빈 화면·오버레이·가로 넘침·JavaScript 오류 없음
- 실제 세션 API와 관리자 세션 API HTTP 200, 익명·MFA 미인증 상태 확인
- 실제 학교 로그인 시작 API HTTP 200, 고정 SmartID HTTPS origin·경로와 관리자 호스트의 콜백 확인
- 이동 주소는 사용자명·비밀번호·fragment를 거부하며, 소스의 주소 검증 7개 조건 확인 통과
- Pretendard `loaded`, 폰트 HTTP 200·2,057,688바이트, 사이드바 216px·상단 바 64px·주 버튼 `#1B64DA`
- localStorage·sessionStorage 저장 0건

학교 비밀번호·TOTP를 입력하지 않았고 실제 관리자 권한 등록이나 실회원 변경은 수행하지 않았습니다. 로그인 시작 응답은 호스트·경로 형태만 확인했으며 state·토큰 원문은 출력하거나 저장하지 않았습니다.

## 2026-10-01 자동 등록·접근 관리 개선

- 학교/등록 관리자 권한과 OTP 요구를 분리했다. OTP가 꺼졌을 때 false인 MFA 상태를 완료로 꾸미지 않고 `authorized`로 진입을 결정한다. 학교 인증 만료는 재로그인으로 안내한다.
- 서버 목록·Paper heartbeat·프록시 등록·접근 모드·개인별 제한의 기준을 서버 API와 맞췄다. 미조회 회원 페이지의 선택 ID를 보존하고 설정 revision을 함께 보내 동시 편집 덮어쓰기를 막는다.
- loopback 합성 API 브라우저에서 OTP 없는 관리자 진입, 서버 목록/신규 비활성 표시, 선택 회원 저장과 CSRF/revision 전송을 확인했다. 데스크톱 1440px·모바일 390px에서 Pretendard 로딩과 가로 넘침 없음을 확인했다.
- 독립 소스 검토에서 새 권한 우회나 선택 대상 유실 문제는 발견되지 않았다. `npm run check`, `npm run build`, `git diff --check`를 통과했다.
- 합성 브라우저 저장 성공은 운영 회원 변경이나 실제 게임 권한 회수 검증을 대신하지 않는다. 운영 배포 기록은 비공개 ops에서 관리한다.

## 2026-10-01 Discord 관리자 해제

검증된 Discord 계정과 역할 상태를 직접 입력한 과거 ID와 구분해 표시한다. 운영자만 회원의 해제 요청을 확인한 뒤 Discord 연결을 해제하고 역할 회수를 요청한다. 접근 정지는 Discord 인증 역할과 게임 접근에 함께 적용하며, 개별 게임 서버 범위 제한은 Discord 역할의 회수 사유가 아니다.

합성 loopback API를 실제 브라우저에서 조작해 확인 체크 전 해제 버튼 비활성, CSRF를 포함한 Discord 대상 DELETE, 목록 갱신, Minecraft 연결 유지, 390px 가로 넘침 없음을 확인했다. TypeScript·production build와 React 구성 검토를 통과했다. 이 검사는 실제 Discord 계정 해제·역할 회수 성공을 뜻하지 않는다.


## Discord 봇 설정과 동기화 상태 · 2026-10-01

- 별도 Discord 봇 메뉴에서 고정 서버/학교 역할, 현재 회원 역할, 현재 학기/누적 역할 매핑, 닉네임 동기화 설정 표시
- TypeScript·production build·설정 검증 단위 2개 통과. role ID 범위, 중복 역할/학기, @everyone, 현재 학기의 누락된 매핑, 40개 제한 포함
- 격리된 루프백 합성 브라우저 시나리오 4개 통과: desktop/mobile 표시, 입력 검증·CSRF/revision 저장과 재동기화 접수, 409 충돌 보존/명시적 재로드·안전한 오류, 관리자 권한 상실 후 설정 화면 제거
- 1440×900·390×844 직접 시각 검토, Pretendard 실제 로드, 모바일 가로 넘침 없음, 런타임 오류 없음
- 학교 역할·현재 회원·학기 역할 설정과 실제 처리 결과를 구분하며, 설정 저장 또는 queued 응답을 역할 반영 성공으로 표시하지 않음
- React 검토: 컴포넌트 분리, 안정된 조회 callback, 세대·abort로 이전 응답 차단, 보이는 탭의 상태 조회, 편집 입력 보존, 명시적 label과 키보드 사용 가능한 기본 입력/버튼
- `/v2/` 프록시를 `/v1/`과 같은 보안 헤더/Host/로그·캐시 정책으로 추가. CI에 실제 nginx와 가상 API의 HTTP smoke 검사 추가. 로컬 Docker daemon은 꺼져 있어 로컬 컨테이너 실행은 하지 않음

실제 관리자 세션·봇 토큰·회원 정보를 읽거나 운영 API를 변경하지 않았습니다. 합성 브라우저는 실제 설치된 agent-browser 0.38.1 바이너리를 사용했고 실행 후 종료했습니다. 초기 npx 실행 지연과 polling 대기 시간을 도구 속도에 기대던 검증 코드는 명시적 실행 파일/조건 대기로 보완했습니다.

## 전체 학번 표시 · 2026-10-01

회원 목록 요약과 펼친 상세의 `학번`에 관리자 API의 `studentId`를 표시합니다. `null`이나 구 API에서 필드가 누락된 경우 `학교 재인증 필요`를 안내하며 입학 연도를 전체 학번으로 표시하지 않습니다. 추가 동의 단계나 조회 요청은 만들지 않았습니다.

합성 데이터 브라우저에서 전체 학번·누락 값 두 경우를 확인하고, 1440×1000·390×844 화면을 직접 검토했습니다. 가로 넘침이 없으며 검색어·학번은 브라우저 저장소나 주소 표시줄에 남기지 않습니다. 운영 회원 정보는 테스트와 스크린샷에 사용하지 않았습니다. 실제 API와 Pages 배포 확인은 배포 후 별도로 진행합니다.

TypeScript·단위 검사 2개·production build와 회원 브라우저 시나리오 7개가 통과했습니다. 기존 통합 검색·필터·정렬·페이지 이동·접근 편집·삭제 확인·통계·권한 만료 시 데이터 제거도 함께 확인했습니다. React 검토에서는 기존 메모리 상태·요청 취소·접근성 구조를 유지하고 별도 효과나 데이터 요청을 추가하지 않은 것을 확인했습니다.

## 다중 운영자 관리 · 2026-10-01

학교 인증 계정을 검색·선택해 owner/operator/viewer 역할로 초대하고, 해당 계정이 직접 수락하는 흐름을 추가했습니다. 초대는 24시간 단회 사용이며 공유 링크·토큰을 생성하지 않습니다. 운영자 역할 변경·회수·초대 취소와 본인/마지막 총괄 운영자 보호를 제공합니다. 조회 전용은 변경 UI를 사용할 수 없으며, 일반 운영자는 운영자 계정을 수정·해제·삭제할 수 없습니다. 서버의 최종 인가는 별도입니다.

- 타입 검사, 단위 2개, production build 통과
- 루프백 합성 브라우저: 대상·역할 확인 후 초대, 취소, 본인 보호, 마지막 owner 경합 오류, 역할 변경·권한 회수, 대상 계정의 수락·만료·대상 불일치 오류, viewer의 모든 변경 영역 제한, operator의 운영자 관리 제한, 역할 상실 시 열린 대화상자 제거, 늦은 검색 응답 폐기
- 기존 회원 7개·Discord 4개 브라우저 회귀 통과
- 데스크톱 1440×900·모바일 390×844 화면 검토, 가로 넘침 없음, 기본 dialog 키보드 포커스와 Escape 취소, 브라우저 저장소·쿼리 토큰 없음
- React 검토: 역할/주체 변경 시 편집 상태를 key로 제거, abort와 요청 세대로 오래된 조회 차단, 명시적 label, 안정된 callback과 정리되는 30초/탭 복귀 조회 사용. 추가 패키지 없음

운영 API의 DB 테스트·실제 초대 수락·Pages 배포는 이 합성 UI 검증과 별개입니다. 실계정에 운영자 권한을 부여하거나 실제 회원 정보를 수정하지 않았습니다. API의 새 session.permissions 배포가 먼저 필요하며, 응답이 없는 경우 변경 기능을 표시하지 않습니다.
